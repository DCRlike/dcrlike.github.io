# Sandbox HTTP API

conchd exposes the Sandbox control-plane API through a local Unix socket. The default socket is `/var/run/conch/conchd.sock`; the actual path is always `<server.work_dir>/conchd.sock`.

```bash
export CONCH_SOCKET=/var/run/conch/conchd.sock
curl --unix-socket "$CONCH_SOCKET" http://localhost/health
```

The current control-plane API does not expose a TCP listener or implement authentication at the HTTP layer. Restrict access to the Unix socket with file permissions.

## Endpoint overview

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/health` | Check whether core control-plane components have initialized. |
| `POST` | `/api/v1/sandboxes` | Create a Sandbox. |
| `GET` | `/api/v1/sandboxes` | List Sandboxes. |
| `GET` | `/api/v1/sandboxes/{sandboxID}` | Get Sandbox details. |
| `DELETE` | `/api/v1/sandboxes/{sandboxID}` | Delete a Sandbox. |
| `PUT` | `/api/v1/sandboxes/{sandboxID}/network` | Replace the complete network policy. |
| `POST` | `/api/sandbox/suspend` | Suspend a Sandbox. |
| `POST` | `/api/sandbox/resume` | Resume a Sandbox. |
| `POST` | `/api/sandbox/checkpoint` | Create a resume Template. |

Except for the multipart endpoint that creates a Template, a JSON request body is limited to 1 MiB. Unknown fields, multiple consecutive JSON values, and non-whitespace content after a JSON value are rejected.

## Health check

```bash
curl --unix-socket "$CONCH_SOCKET" \
  -i http://localhost/health
```

The endpoint returns `204 No Content` when the core components are ready. It confirms that the state store, containerd host, daemon client, and runtime service have initialized; it does not probe their ongoing real-time health individually.

## Create a Sandbox

```bash
curl --unix-socket "$CONCH_SOCKET" \
  -X POST http://localhost/api/v1/sandboxes \
  -H 'Content-Type: application/json' \
  -d '{
    "sandbox_id": "sandbox-demo",
    "template_name": "localhost/conch/python:latest",
    "vcpu_num": 2,
    "vcpu_max": 2,
    "ram_mb": 4096,
    "env": {
      "WORKLOAD": "docs-demo"
    },
    "network": {
      "allowOut": ["198.51.100.10"],
      "denyIn": ["203.0.113.0/24"],
      "allow_internet_access": false
    },
    "volumeMounts": [
      {
        "source": "/srv/conch/workspace",
        "path": "/workspace",
        "readonly": false
      }
    ]
  }'
```

### Request fields

| Field | Type | Description |
| --- | --- | --- |
| `sandbox_id` | string | Optional. Generated by conchd when omitted. An explicit value is 2–32 characters, uses only letters, numbers, `_`, `.`, and `-`, and starts with a letter or number. |
| `template_name` | string | Optional. Mutable Template Name; mutually exclusive with `template_id`. |
| `template_id` | string | Optional. Immutable OCI digest; mutually exclusive with `template_name`. |
| `vmm_name` | string | Optional. VMM name such as `stratovirt` or `cloud-hypervisor`. |
| `vcpu_num` | integer | Optional. Initial number of vCPUs. |
| `vcpu_max` | integer | Optional. vCPU limit; must not be less than `vcpu_num`. |
| `ram_mb` | integer | Optional. Memory in MiB. An explicit value has a minimum of 128 and a fixed maximum of 262144. |
| `env` | object | Optional. String key-value pairs passed to the guest initialization environment. |
| `network` | object | Optional. IPv4 network policy applied at creation time. |
| `volumeMounts` | array | Optional. List of host-directory mounts. |

When Template and resource fields are zero values or empty strings, conchd uses `sandbox.default_spec` and `sandbox.backend`. After defaults are applied, exactly one of `template_name` and `template_id` must exist. The fixed vCPU limit is 64.

Defaults are applied independently to `vcpu_num` and `vcpu_max`. If you explicitly raise `vcpu_num` above the default `vcpu_max`, also pass a `vcpu_max` that is at least as large.

An `env` key cannot be empty or contain `=` or NUL; its value cannot contain NUL. The Sandbox ID, Agent token, network configuration, and environment variables form the guest initialization message, which is limited to 16 KiB after UTF-8 encoding.

Network policy fields are `allowOut`, `denyOut`, `allowIn`, `denyIn`, and `allow_internet_access`. The four lists accept only IPv4 addresses or CIDRs, with no more than 1024 entries in total. See the [Storage Reference](/docs/reference/storage) for Volume fields.

### Success response

```json
{
  "templateName": "localhost/conch/python:latest",
  "templateID": "sha256:0123456789abcdef...",
  "sandboxID": "sandbox-demo",
  "conchInitVersion": "",
  "alias": "",
  "conchInitAccessToken": "<token>",
  "domain": "192.0.2.10"
}
```

`conchInitAccessToken` authorizes access to the conch-init Agent API inside the guest and must be treated as a credential. The token is returned only in the creation response, not in later GET responses.

## List Sandboxes

```bash
curl --unix-socket "$CONCH_SOCKET" \
  'http://localhost/api/v1/sandboxes?state=running&limit=100'
```

Query parameters:

| Parameter | Description |
| --- | --- |
| `state` | Repeatable. Accepts `running` and `paused`, which correspond to internal `READY` and `SUSPENDED`. |
| `limit` | 1–5000; defaults to 100. |

When `state` is omitted, the endpoint still returns only running or suspended records; internal states such as `CREATING` and `UNKNOWN` are excluded.

```json
[
  {
    "templateName": "localhost/conch/python:latest",
    "templateID": "sha256:0123456789abcdef...",
    "imageName": "",
    "snapshotID": "",
    "sandboxID": "sandbox-demo",
    "startedAt": "2026-09-01T08:00:00Z",
    "endAt": "",
    "cpuCount": 2,
    "memoryMB": 4096,
    "diskSizeMB": 0,
    "conchInitVersion": "",
    "alias": "",
    "metadata": {},
    "volumeMounts": []
  }
]
```

The current list response does not include `domain`, `network`, or lifecycle details.

## Get Sandbox details

```bash
curl --unix-socket "$CONCH_SOCKET" \
  http://localhost/api/v1/sandboxes/sandbox-demo
```

In addition to list fields, the detail response includes `domain`, `lifecycle`, and `network`:

```json
{
  "templateName": "localhost/conch/python:latest",
  "templateID": "sha256:0123456789abcdef...",
  "imageName": "",
  "snapshotID": "",
  "sandboxID": "sandbox-demo",
  "startedAt": "2026-09-01T08:00:00Z",
  "endAt": "",
  "cpuCount": 2,
  "memoryMB": 4096,
  "diskSizeMB": 0,
  "conchInitVersion": "",
  "alias": "",
  "domain": "192.0.2.10",
  "metadata": {},
  "lifecycle": {"autoResume": false},
  "volumeMounts": [],
  "network": {
    "allowOut": ["198.51.100.10"],
    "denyIn": ["203.0.113.0/24"],
    "allow_internet_access": false
  }
}
```

`imageName`, `snapshotID`, `diskSizeMB`, `conchInitVersion`, `alias`, `metadata`, and `lifecycle.autoResume` are compatibility or reserved fields in the current response. `volumeMounts` is not currently restored from persistent state and always returns an empty array.

## Update the network policy

```bash
curl --unix-socket "$CONCH_SOCKET" \
  -X PUT http://localhost/api/v1/sandboxes/sandbox-demo/network \
  -H 'Content-Type: application/json' \
  -d '{
    "allowOut": ["198.51.100.10"],
    "denyOut": [],
    "allowIn": [],
    "denyIn": ["203.0.113.0/24"],
    "allow_internet_access": false
  }'
```

Success returns `204 No Content`. This endpoint replaces the existing policy in full; omitted arrays are treated as empty. Both running and suspended Sandboxes can be updated.

Deny rules take precedence over allow rules. A non-empty allow list enables an allowlist for that direction. With only a deny list, unmatched traffic remains allowed. `allow_internet_access: false` denies egress traffic not accepted by another rule. Existing conntrack connections are allowed first and are not guaranteed to disconnect immediately after an update.

## Suspend and resume

Suspend:

```bash
curl --unix-socket "$CONCH_SOCKET" \
  -X POST http://localhost/api/sandbox/suspend \
  -H 'Content-Type: application/json' \
  -d '{"sandbox_id":"sandbox-demo"}'
```

Resume:

```bash
curl --unix-socket "$CONCH_SOCKET" \
  -X POST http://localhost/api/sandbox/resume \
  -H 'Content-Type: application/json' \
  -d '{"sandbox_id":"sandbox-demo"}'
```

Both return:

```json
{"status":"ok"}
```

Suspend pauses execution while retaining the VMM, network, and Volume resources. Resume continues the same Sandbox. This is not a persistent checkpoint.

## Create a checkpoint Template

```bash
curl --unix-socket "$CONCH_SOCKET" \
  -X POST http://localhost/api/sandbox/checkpoint \
  -H 'Content-Type: application/json' \
  -d '{
    "sandbox_id": "sandbox-demo",
    "template_name": "localhost/conch/python-ready:latest",
    "labels": {
      "purpose": "docs"
    }
  }'
```

`sandbox_id` and `template_name` are required. A successful response is:

```json
{
  "status": "ok",
  "template_id": "sha256:fedcba9876543210..."
}
```

A checkpoint creates a resume Template without changing the source Sandbox's running state. Sandboxes with Volumes do not support checkpoints.

## Delete a Sandbox

```bash
curl --unix-socket "$CONCH_SOCKET" \
  -X DELETE http://localhost/api/v1/sandboxes/sandbox-demo
```

Success returns `204 No Content`. A missing target returns `404`, so the HTTP delete endpoint does not use idempotent-success semantics.

## Error responses

Failures use a consistent JSON structure:

```json
{
  "status": "error",
  "code": "sandbox.invalid_argument",
  "error": "invalid sandbox argument"
}
```

Use `code` for automation; `error` is the public user-facing message. Common HTTP mappings include:

| HTTP status | Meaning |
| --- | --- |
| `400` | Invalid request fields or JSON. |
| `404` | Sandbox or Template not found. |
| `409` | ID conflict or state does not satisfy an operation precondition. |
| `413` | Request body or initialization payload is too large. |
| `429` | A fixed resource limit was exceeded. |
| `503` | The control plane is not ready. |
| `504` | Request timed out. |
