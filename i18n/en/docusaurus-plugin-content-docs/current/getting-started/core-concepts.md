# Core Concepts

This page defines the concepts shared throughout the Conch documentation. See the User Guide and Reference for procedures and field-level details.

## Sandbox

A Sandbox is a microVM-isolated environment for Agent workloads. Every Sandbox starts from a Template and has an independent VMM process, network resources, and in-guest `conch-init`. `conch-init` provides command execution, background-process, and file-transfer APIs.

When creating a Sandbox, you can specify CPU, memory, environment variables, network policy, and Volumes. conchd fills omitted Template and resource fields from `sandbox.default_spec`. The caller can provide a Sandbox ID or let Conch generate one.

## Template

A Template is a bootable object used to create a Sandbox and maps one-to-one to an OCI Boot Index. Each Template has both:

- A `Template Name`: a readable, reusable name such as `localhost/conch/python:latest`. Writing the same name again makes it point to a new Template ID.
- A `Template ID`: the OCI digest of the Boot Index, such as `sha256:...`. It is immutable after the content is created.

Choose either `template_name` or `template_id` when creating a Sandbox. A Template can be built from a regular OCI Image or generated by checkpointing a running Sandbox.

## Image

An Image is a regular OCI image containing a rootfs and application content. It can serve as input for a cold Template but cannot create a Sandbox directly. Conch converts the Image rootfs to EROFS and publishes it together with the guest kernel and initrd as a Boot Index.

## Snapshot

A Snapshot is a containerd snapshot managed internally by Conch. After a user creates a checkpoint, the result is a Template with `boot_mode=resume`, not a separate Snapshot resource that must be managed. The Template contains restorable VMM memory state and records its parent Template ID and source Sandbox ID.

A checkpoint does not delete the source Sandbox or change its running state. Sandboxes with Volumes do not currently support checkpoints, and a Sandbox started from a resume Template cannot mount Volumes.

## Network Slot and Volume

- A Network Slot is a pre-created, allocatable, and recyclable set of Sandbox network resources.
- A Volume mounts an existing host directory at a specified path inside the guest.

A Network Slot provides the Sandbox CNI address, network namespace, guest tap, and address translation. A `network` policy accepts only IPv4 addresses or CIDRs and restricts guest ingress and egress.

Volumes currently use virtiofs. `source` is an absolute directory on the host running conchd, while `path` is an absolute target inside the guest. Deleting a Sandbox does not delete host data.
